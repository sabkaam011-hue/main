# Content & verification workflow

Sabkaam must **never invent scheme details, benefits, eligibility or deadlines**.

## Status levels
| Status | Meaning | Public page |
|---|---|---|
| `demo` | Sample data shipped with the codebase | Amber "Demo data" badge + warning |
| `unverified` | Entered by an editor but not yet checked | Same warning |
| `verified` | Checked line by line against the official source | Green "Verified" badge + "Last verified" date |

All 55 seed records are `demo`. They contain only high-level, widely published descriptions, link to official portals, and avoid amounts, limits and dates. Even these must be verified before launch.

## Verifying a record (Admin → Services & listings → edit)
1. Open the **official URL**. Use only primary sources: the ministry or department portal, the official guidelines PDF, or the gazette notification. Never use news or aggregator sites.
2. Check each field: overview, benefits (amounts exactly as notified), eligibility, documents, steps, dates.
3. For time-bound items (scholarships, recruitment), add **Important dates** in the format `Label | YYYY-MM-DD | note`. Leave the date blank for "as notified".
4. Add Hindi title and summary, plus search keywords (Hindi, Hinglish and common misspellings).
5. Set the **fee** and **What's included**, or leave the fee blank for information-only.
6. Set status to **Verified** (this stamps today's date) and save.
7. Re-verify on a schedule (suggestion: every 90 days, and whenever a new notification is issued). Filter the services list by *Verified* and sort by updated date to find stale records.

## Job, exam and scholarship listings
Use type `job`, `exam` or `scholarship` with Important dates for openings. Only publish a listing once you have the official notification PDF. Unpublish expired listings rather than deleting them if requests reference them.

## Tone
Plain language, short sentences, no promises ("guaranteed", "100% approval"), and always "apply on the official website" alongside "get assistance".
